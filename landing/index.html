Features

Everything you need to tame local dev

PortPilot reads your system in real-time — no config files, no plugins, no setup.

Instant visibility

See every local port, the process behind it, which project directory it lives in, and what command started it — all in one compact panel.

Smart detection

Automatically identifies frameworks (Next.js, Vite, Rails…), package managers, and Docker containers — so you always know what's what.

Search & filter

Filter by port number, project name, alias, PID, command, framework, package manager, Docker image, or container ID — as you type.

One-click actions

Open the local URL in your browser, copy it to clipboard, reveal the project folder in Finder, or rename a port with a custom alias.

Docker-aware

Detects Docker containers alongside regular processes. Stop a container with docker stop without touching the Docker backend itself.

System & dark themes

Follows your macOS appearance automatically, or lock it to light or dark. The panel always feels at home on your desktop.

How it works

Zero setup. Just run it.

PortPilot uses lsof and ps to read your system state — no root permissions, no daemons, no config files.

1
Install & launch

Download the .dmg, drag PortPilot to Applications, and open it. It appears as a small icon in your menu bar immediately.

2
Click the icon

A compact panel drops down showing every active local port with project info, framework tags, and quick actions. No windows, no Dock clutter.

3
Stop what you don't need

Hit Stop to send SIGTERM. If it hangs, Force Stop appears. Protected system processes are marked and cannot be stopped.

Safety model

Designed to never surprise you

Stopping a process you didn't mean to is painful. PortPilot puts multiple guardrails between you and an accidental kill.

  • Shell commands only run in the Electron main process — the renderer never touches the shell.
  • SIGTERM is sent first. SIGKILL is only available if the process survives and you explicitly click Force Stop.
  • Protected system processes are flagged and cannot be stopped — even if they're holding a port.
  • Stop actions operate only on records the scanner knows about and the main process re-validates before acting.
  • Docker containers use docker stop — the Docker Desktop backend is never touched directly.
