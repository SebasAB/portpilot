Frequently asked

Quick answers

What does PortPilot actually do?

PortPilot is a macOS menu bar utility that shows you what's running on your local ports. It identifies the process, the project directory, the framework (Next.js, Vite, Rails, etc.), and whether the port is bound by a Docker container — then lets you stop it safely.

Why doesn't the Stop button work on some processes?

There are a few reasons a port might be unstoppable:

  • Protected system process — macOS daemons like mDNSResponder or coreaudiod are flagged dangerous-to-stop and the button is disabled.
  • Permission — the process is owned by another user (typically root) and the sandboxed app cannot send it a signal.
  • It survived SIGTERM — in that case a red Force Stop button appears, which sends SIGKILL.
What's the difference between Stop and Force Stop?

Stop sends SIGTERM, asking the process to shut down cleanly. Most servers and tools handle this gracefully — they close connections, flush buffers, and exit. This is always the first attempt.

Force Stop sends SIGKILL, which immediately terminates the process without giving it a chance to clean up. PortPilot only shows this option if SIGTERM failed and the process is still listening on the port.

Does PortPilot work on Intel Macs?

v0.1 of PortPilot ships for Apple Silicon (arm64) only. An Intel (x86_64) build is on the roadmap once we've validated arm64 in the App Store.

How does PortPilot detect Docker containers?

PortPilot runs docker ps to list running containers and reads their port mappings. If the Docker CLI is not installed or Docker Desktop is not running, PortPilot will silently skip the Docker scan — your regular processes still show up normally.

Stopping a Docker-backed port calls docker stop <containerId>. PortPilot never sends signals to the Docker backend itself.

What permissions does PortPilot need?

PortPilot runs in Apple's sandbox with the minimum entitlements needed:

  • Read process and port information via lsof and ps.
  • Send SIGTERM / SIGKILL only to processes you explicitly select.
  • Open URLs in your default browser when you click Open.
  • Reveal folders in Finder when you click Reveal.

It does not request network access, location, contacts, camera, microphone, or full disk access.

Where does PortPilot store my settings?

On your Mac, in the app's sandboxed container under ~/Library/Containers/dev.portpilot.app/. Theme preference, search history, filter state, and custom aliases live there. No settings are synced with iCloud or any remote service.

Is PortPilot free?

Yes. PortPilot is free to download from the Mac App Store. There are no in-app purchases, no subscription tiers, no paid features, and no ads.
